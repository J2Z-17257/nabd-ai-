# نبض

**طبقة الربط بين بنوك الدم — الرياض**

منصّة تُظهر مخزون الدم في ١٣ بنك دم في مكان واحد، تتنبأ بالنقص قبل وقوعه بـ٧٢ ساعة،
وتطابق الطلب العاجل بأقرب مصدر متوافق آلياً.

</div>

---

## المشكلة

الوحدة صالحة ٤٢ يوماً فقط. الطلب يتذبذب مع العمليات المجدولة والحوادث، والتبرع ينخفض موسمياً.
كل بنك دم يرى مخزونه وحده، فيحدث **النقص والهدر في نفس المدينة وفي نفس اليوم**: مستشفى يؤجّل عملية
لعدم توفر فصيلة، ومستشفى آخر على بُعد ثمانية كيلومترات يتلف عنده نفس الفصيلة بانتهاء الصلاحية.

زمن المطابقة اليدوية بين المستشفيات يقارب ثلاث ساعات ونصف. نبض يختصره إلى **٤٧ ثانية**.

## التشغيل السريع

انقر نقرة مزدوجة على `index.html`. لا يحتاج شيئاً آخر.

أو شغّله على خادم محلي:

```bash
python3 -m http.server 8787
# ثم افتح http://localhost:8787
```

### مدخلان في شاشة البداية

**منسوبو المستشفى** — مخزون منشأتك وطلباتها وتنبؤها وحدها. للأطباء ومسؤولي بنك الدم وفنيي المختبر.

**منصة نفيس** — الإشراف الإقليمي على بنوك الرياض كاملة. لمصرف الدم الإقليمي ومراقبة الجودة وتقنية المعلومات.

للتصفح الحر: اكتب **أي اسم مستخدم** وادخل. الحسابات التجريبية أدناه تحتفظ بأدوارها المقيّدة
لأن الفصل بين الأدوار هو جوهر العرض لا تفصيل فيه.

| الحساب | المدخل | الدور | ما يراه |
|---|---|---|---|
| `f.alqahtani` | نفيس | مدير مصرف الدم الإقليمي | ١٣ منشأة · كل الصلاحيات التشغيلية |
| `h.almutairi` | نفيس | مراقبة الجودة | ١٣ منشأة · يرى ولا يعتمد |
| `y.alzahrani` | نفيس | مسؤول تقنية المعلومات | **صفر بيانات سريرية** مع تفسير |
| `n.alharbi` | مستشفى | مسؤولة بنك الدم | مدينة الملك سعود الطبية |
| `m.alotaibi` | مستشفى | فنية مختبر | الملك فيصل التخصصي · للاطلاع فقط |
| `a.alshehri` | مستشفى | استشاري جراحة | اليمامة · يملك **إعلان الطوارئ** |

جرّب حساباً من المدخل الخطأ: يحوّلك تلقائياً للمدخل الصحيح ويشرح السبب.

## الشاشات

### غرفة عمليات الرياض
خريطة المنطقة بـ١٣ بنك دم: المربع الأحمر حرج، المثلث منخفض، الدائرة كافٍ، وحجم الشكل يعكس سعة البنك.
خط متقطع يربط البنك الطالب بالمصدر المطابَق مع زمن الوصول.

![غرفة العمليات](docs/screens/01-ops-room.png)

### بنوك الدم
جدول ١٣ منشأة بالنطاق والقطاع وإجمالي الوحدات والمتوفر مقابل الحد الآمن، مع تصفية بالحالة.

![بنوك الدم](docs/screens/02-banks.png)

### صندوق الطلبات
الطلبات المفتوحة مع المطابقة الآلية: أقرب بنك يملك فائضاً من الفصيلة المطلوبة، والمسافة وزمن الوصول.

![صندوق الطلبات](docs/screens/03-inbox.png)

### تنبؤ نبض
مسار المخزون المتوقع خلال ٧٢ ساعة مقابل نصف الحد الآمن، والبنوك المهددة، والهدر المتوقع خلال سبعة أيام.

![تنبؤ نبض](docs/screens/04-forecast.png)

## محرك التنبؤ

```bash
cd engine
pip install -r requirements.txt
python main.py --horizon 14
python tests/test_smoke.py
```

**المنهجية باختصار:**

- **تنبؤ متعدد الآفاق مباشر** — لكل فصيلة ولكل أفق h يُدرَّب نموذج مستقل، فلا يتراكم الخطأ يوماً بعد يوم.
- **ثلاث قيم لا قيمة واحدة** (p10 / p50 / p90) — بنك الدم يقرر على أسوأ حالة معقولة لا على المتوسط.
- **محاكاة FIFO مع الصلاحية** — بدونها يظهر رقم مخزون لا يعكس الهدر القادم.
- **سيناريو ضغط مُدرَّج بـ √الزمن** — تطبيق الحد الأدنى اليومي على ١٤ يوماً متتالياً خطأ شائع يجعل
  كل الفصائل حمراء دائماً فيفقد النظام مصداقيته.

النموذج يتفوق على خط الأساس (Seasonal Naive) بنحو **٢٤٪** في متوسط الخطأ عبر آفاق ١ و٧ و١٤ يوماً.

تفاصيل أوفى في [`engine/README.md`](engine/README.md).

## حدود العرض الحالي

البيانات في هذا المستودع **مرجعية للتجربة** ولا تمثل مخزوناً فعلياً لأي جهة، وشارة
«بيانات تجريبية للعرض» ظاهرة في الترويسة عمداً. لا تُزَل إلا بعد ربط مصدر حقيقي.

تصفية الصلاحيات في `index.html` تقع في المتصفح — كافية للعرض ويمكن تجاوزها بأدوات المطوّر.
في التشغيل الحقيقي يجب أن تقع على الخادم قبل الإرسال.

النظام **أداة دعم قرار**، لا بديل عن الحكم الطبي. قرار نقل الدم والإحلال المتوافق يبقى للطبيب المختص.

## الخطوات القادمة

1. **REST API** يغلّف محرك التنبؤ (`GET /forecast`، `GET /alerts`، `POST /ingest`).
2. **ربط الواجهة** بالمحرك بدل توليد الأرقام داخل المتصفح.
3. **قاعدة بيانات** لحفظ التنبؤات ومقارنتها بالواقع — هي ما يحوّل «نتوقع أن يكون دقيقاً» إلى رقم مُثبت.
4. **نقل الصلاحيات إلى الخادم** مع سجل تدقيق.
5. **إشعارات موجّهة** للمتبرعين المؤهلين للفصيلة الناقصة تحديداً.
